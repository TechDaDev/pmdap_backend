# M14 Audit, Integrity, and Security Hardening Implementation Plan

**Goal:** Append-only, privacy-sanitized audit log over security-significant
actions; medical file-integrity verification; hardening sweep (IDOR, mass
assignment, search injection, logging, constraints, concurrency,
performance); stop before M15.

## Tasks

1. Design spec/plan/ADR and ADR README update.
2. `audit` app: `AuditLog` model (append-only guards, 4 indexes),
   `audit/services.py` (redaction, request-id, `record_audit`),
   read-only `audit/admin.py`.
3. `common.middleware.AuditRequestIdMiddleware` + settings wiring.
4. Wire audits into services:
   - `accounts.services.register_account` → `ACCOUNT_CREATED`
   - `identities.services` (upload/verified/rejected/replaced + SYSTEM
     status change)
   - `guardians.services` (minor created, relationship submit/verify/reject)
   - `claims.services` (submit, more-info, reject, approve, link,
     activation created, access expired, activated)
   - `documents.services` (uploaded, type/facility/metadata updated, deleted)
   - `documents.date_services` (confirmed/corrected)
   - `processing.services` + `ocr_services` (PDF/OCR failure, integrity
     failure)
5. Integrity hardening: `MISSING` status, `verify_stored_file_integrity`
   (atomic, size+SHA-256, no byte mutation), stream gate includes MISSING,
   `verify_medical_file_integrity` management command (safe count output).
6. Migrations: `audit.0001`, `documents.0009` (integrity status).
7. Tests: model, service (redaction), wiring, integrity, secrets, IDOR
   sweep, mass assignment, search injection (PG), logging, concurrency (PG),
   constraints (PG), performance/EXPLAIN (PG), e2e.
8. PostgreSQL: persistent forward migration (52 -> 54), fresh migration from
   zero, full PG suite, audit concurrency/perf on PG.
9. Gates: Ruff, format, checks, drift, OpenAPI, `pip check`, Docker compose
   validation, web + worker builds, health, Celery ping/smoke, coverage >= 90%.
10. Commit clean M14 work (exclude owner files); report; stop before M15.
