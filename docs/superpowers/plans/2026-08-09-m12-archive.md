# M12 Chronological Medical Archive Implementation Plan

**Goal:** Deliver metadata-driven chronological archive views with verified-date
chronology, an explicit unconfirmed-date bucket, grouping summaries, and stable
pagination; stop before M13 search.

## Tasks

1. Add `archive` query layer (`ArchiveQueryService`), filter serializer, archive
   document serializer, and list + summary views for adult and minor routes.
2. Add `documents` migration with three archive indexes
   `(patient, archive_status, document_date)`, `(patient, archive_status,
   document_type)`, `(patient, archive_status, healthcare_facility)`.
3. Add OpenAPI contracts and query-parameter documentation for archive routes.
4. Write tests: adult chronology/ties/deletion/isolation, guardian
   father/mother/pending/rejected/inactive/unrelated/age-18, unconfirmed
   bucket, soft-delete exclusion, M9/M10/M11 authority integration, date
   correction repositioning, classification/facility reflection, pagination,
   summary counts, filter validation, verification-agent isolation, query-count
   regression, read-only invariants.
5. PostgreSQL: persistent forward migration (50 -> 51, tables stay 36), fresh
   migration from zero, concurrency consistency (read vs soft delete/date/type/
   facility), performance sanity on 1,000–10,000 documents.
6. End-to-end M6->M12 lifecycle and M10 correction repositioning; upstream
   Celery smoke; Docker Compose validation + image builds + service health.
7. Run targeted and full M0–M12 suite on PostgreSQL, branch coverage >= 90%,
   Ruff, formatting, Django checks, migration drift, OpenAPI validation,
   `pip check`; commit clean phase-scoped work; report and stop before M13.
